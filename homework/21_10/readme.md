# Отчет по домашней работе: Обработка сетевых ошибок и завершение потоков в PyQt6

## 1. Внесенные изменения
- В класс `ReceiveThread` добавлен сигнал `connection_lost` и блок перехвата сетевых ошибок в методе `run()`.
- В класс `SendThread` добавлен метод `stop()`, передающий маркер остановки `None` в очередь `Queue`.
- В класс `MainWindow` добавлен обработчик `on_connection_lost` и переопределен метод `closeEvent`.
- Исправлена опечатка в обработчике кнопки очистки истории (`self.history.clear`).

## 2. Обработка потери соединения
Сетевой вызов `self.net.recv()` обернут в блок `try-except OSError`. 
- При аварийном обрыве соединения (падение сервера, сетевой сбой) перехватывается исключение `OSError`.
- При корректном отключении сервера проверяется возврат значения `None`.
В обоих случаях генерируется сигнал `self.connection_lost.emit()` и выполняется `break` для завершения цикла потока. Сигнал передается в главный поток интерфейса, где меняется статус на `Disconnected`, блокируются элементы ввода и выводится уведомление в чат.

## 3. Остановка SendThread
Остановка реализована через паттерн Poison Pill (сторожевое значение). При вызове метода `stop()` в очередь `self.queue` отправляется `None`. Поток `SendThread`, находящийся в блокирующем ожидании `self.queue.get()`, считывает `None`, выходит из цикла `while True` и безопасно завершает работу.

## 4. Завершение работы приложения (closeEvent)
В методе `closeEvent` организована строгая последовательность завершения:
1. Вызов `self.send_thread.stop()` и ожидание завершения через `self.send_thread.wait()`.
2. Принудительное закрытие клиентского сокета через `shutdown` и `close()`, что прерывает блокирующий системный вызов `recv()` в читающем потоке.
3. Ожидание завершения читающего потока через `self.receive_thread.wait()`.
4. Подтверждение закрытия окна `event.accept()`.
Это исключает взаимные блокировки (Deadlock) и предотвращает ошибку `QThread: Destroyed while thread is still running`.

## 5. Выполненные проверки
1. **Штатная работа:** отправка и получение сообщений без дублирования.
2. **Аварийная остановка сервера:** при завершении `server.py` клиент корректно фиксирует потерю связи, интерфейс блокируется, исключения в консоль не выбрасываются.
3. **Закрытие клиента:** при закрытии окна процесс завершается мгновенно, фоновые потоки не зависают.
